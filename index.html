필드는 전부 private으로 숨기고, 밖에서 꼭 필요한 기능만 public 메서드로 열었어요.

검증 메서드도 private이에요. 계정 안에서만 쓰는 도구라서 밖에 보여줄 이유가 없거든요.

나와 전 애인 모두 같은 클래스로 만든 서로 다른 객체예요.

필드와 생성자

private String owner; private String mainId; // 본계 private String subId; // 부계 private String[] blockedIds; // 차단 목록 private int blockedCount; public InstaAccount(String owner, String mainId, String subId) { this.owner = owner; this.mainId = validateId(mainId); this.subId = validateId(subId); this.blockedIds = new String[5]; this.blockedCount = 0; }

this.owner는 객체의 필드, 그냥 owner는 매개변수예요.

this를 빼면 매개변수에 자기 자신을 넣는 꼴이라, 필드는 계속 비어 있어요. 직접 지워보고 확인했어요.

아이디는 생성자에서 들어오자마자 검증해요. 잘못된 계정은 처음부터 못 만들어요.

getter를 안 만드는 것도 설계예요

public String getMainId() { return mainId; } // getSubId() 안 만듦 🤫 // setBlockedIds() 안 만듦 🔒 // getBlockedIds() 안 만듦 📦 public int getBlockedCount() { return blockedCount; // 숫자만 공개 }

본계 아이디는 알려져도 괜찮으니까 getter를 열어뒀어요.

부계는 존재 자체를 숨겨야 해서 getter가 없어요. 밖에서는 읽을 방법이 아예 없어요.

차단 목록은 setter가 없어서 오직 block()으로만 바뀌어요.

배열을 통째로 돌려주는 getter도 안 만들었어요. 배열을 받으면 밖에서 [0] = ""처럼 안의 값을 바꿀 수 있거든요. 대신 인원 수만 공개해요.

검증 메서드: 새벽 "자니?" 방어

public String receiveDM(InstaAccount sender, String message, int hour) { if (hour < 0 || hour > 23) return "시간오류"; if (message.trim().length() == 0) return "빈메시지"; if (isBlocked(sender.getMainId())) return "차단상태"; if (isDawn(hour) && message.contains("자니")) { block(sender.getMainId()); return "자동차단"; } return "도착"; }

검증은 네 단계예요. 없는 시간인지, 빈 메시지인지, 이미 차단된 사람인지, 새벽 "자니?"인지.

새벽 1~5시에 "자니"가 들어간 메시지는 보낸 사람을 자동 차단해요.

처리 결과를 문자열로 돌려줘서, 시뮬레이터가 "왜 이렇게 됐는지"를 설명할 수 있어요.

배열로 여러 명 차단하기

public void block(String targetId) { if (isMine(targetId)) return; // 내 계정 if (isBlocked(targetId)) return; // 중복 // 꽉 참 if (blockedCount >= blockedIds.length) return; blockedIds[blockedCount] = targetId; blockedCount++; } private boolean isBlocked(String id) { for (int i = 0; i < blockedCount; i++) { if (blockedIds[i].equals(id)) return true; } return false; }

차단 목록을 크기 5인 배열로 바꿔서, 본계와 부계를 모두 막을 수 있어요.

추가하기 전에 세 가지를 검증해요. 내 계정인지, 이미 차단했는지, 목록이 꽉 찼는지.

차단 여부는 반복문으로 배열을 한 칸씩 확인해요.

심화: private은 클래스 단위예요

// InstaAccount 클래스 "안"에서는 public void spy(InstaAccount target) { System.out.println(target.subId); // 컴파일 OK 😱 }

Java의 private은 객체마다가 아니라 클래스마다 막아요.

그래서 같은 클래스 안에서는 다른 객체의 private 필드도 읽을 수 있어요. 3막에서 막혔던 건 Main이라는 다른 클래스였기 때문이에요.

결국 진짜 보안은 클래스를 설계하는 사람의 책임이에요.
